# Interface direction

## Research and showcase, September 2026

Keep the existing paper, workspace, ink, slate, pine and ochre tokens and IBM Plex Sans. Add a public, static product tour with a recruiter/technical audience switch. Its memorable element is a submission crossing a feedback boundary: the learner sees one bit while the researcher can inspect the assessment. Show an explicitly illustrative document, never fabricated performance claims. The research view uses a partition rail (train, validate/freeze, test, human review) and an aligned method comparison plot. Empty results show what must run, not invented numbers.

```text
showcase: audience choice | problem + inspectable document/feedback example
research: study selector | split rail | next stage + registered call budget
                         | paired results by method | frozen policies + audit
```

Reviewed against the brief: a generic dashboard of success percentages would conceal the scientific question. Keep opportunity-level uncertainty, freeze state, and actual feedback allowances visible instead. Recruiter copy explains the user benefit; technical copy explains controls and known limits. Stack the document and inspector on mobile.

## Operable agent workflow, September 2026

The entry point becomes a submission studio: the draft is the focal object, with a two-column document/strategy workspace. A short brief and artifact type replace reference-generator knobs. One primary action develops two competing drafts; the next action explores a new round. Show genuine stage progress, saved outputs, and failures with recovery instructions. Put evaluator internals in the existing experiment inspector. Keep the pine/slate palette and IBM Plex typography. Leave the reference laboratory under advanced tools, clearly separated from Kimi-generated work. Avoid a chat box that hides durable results.

```text
project navigation | artifact type + short brief      [Develop submission]
                   | actual agent stages and recorded call counts
                   | selected draft (wide) | strategy, lineage, binary record
                   | alternatives and next-round action
```

This revision centers a usable submission rather than setup fields and synthetic scores. Keep manual editing and evidence addition one click away; explain missing evidence before starting paid calls.

The application is a research workbench for comparing applications. Its distinctive element is the inspectable boundary between the learner's binary observation and the user's complete evaluation.

- Paper `#ffffff`: drafts and inspectable records.
- Workspace `#f3f6f7`: quiet background.
- Ink `#20343d`: primary text.
- Slate `#23434b`: navigation and structural emphasis.
- Pine `#246557`: active selection and successful outcomes.
- Ochre `#9b661c`: synthetic-data and reference-model notices.

IBM Plex Sans carries headings, body text, and tabular data. Use a restrained scale, sentence-case labels, and generous space around the main comparison. Avoid decorative metric cards. The navigation is persistent, with a project selector above the brief, evidence, strategies, and experiments.

```text
project navigation | page title and primary action
                   | project context / comparison workspace
                   | selected strategy or trial details
```

The initial view presents a synthetic project with computed reference trials. No fabricated AI activity, external acceptance odds, or implied real institutions. The trial inspector gives equal prominence to the exact feedback delivered and the observer's score details. The desktop layout folds into a horizontal navigation and stacked content on narrow screens.

Reviewed against the brief: the interface centers experiment records and policy ancestry rather than a generic analytics dashboard. The app's evidence labels, known/assumed distinctions, and feedback inspector provide its visual structure.
